# Руководство по наполнению базы знаний и файлов

**Для кого:** администраторы, добавляющие или редактирующие записи в
админ-панели ([admin.py](../admin.py)).
**Цель:** сделать каждую запись находимой векторным поиском и полезной для
LLM, чтобы бот давал полные и корректные ответы.

Если нет времени читать всё — прочитайте раздел **«Ментальная модель за 60
секунд»** и **Чек-лист** в конце.

---

## 1. Ментальная модель за 60 секунд

Студент задаёт боту вопрос. Бот:

1. **Векторизует вопрос** моделью `intfloat/multilingual-e5-base`
   (768 измерений, мультиязычная — русский, казахский, английский).
2. **Находит 3 ближайших записи** в базе знаний по косинусному расстоянию.
   Записи с расстоянием `> 0.35` отбрасываются.
3. **Собирает контекст** из прошедших фильтр записей и передаёт его в LLM с
   жёсткой инструкцией: *отвечай ТОЛЬКО по этому тексту, ничего не
   выдумывай*. Если контекст пустой — бот отказывается отвечать без вызова
   LLM.
4. **Прикрепляет файлы** двумя способами:
   - **Курированный (основной)** — файл, который администратор явно привязал
     к найденной записи, всегда прикрепляется. Без порогов и догадок.
   - **Векторный fallback** — файл, чьи `keywords` пересекаются с запросом,
     расстояние `≤ 0.20`, и есть явный лидер (разрыв `≥ 0.05` до следующего
     файла с совпадающим ключевым словом).

Два следствия, которые определяют всё остальное:

- **LLM не видит вопроса — только контекст, который написали вы.** Если в
  вашей записи нет шага, дедлайна или контакта, бот не сможет их придумать.
- **Эмбеддинг-модель видит только текст.** Для файлов это означает
  `title + caption + keywords + category` — модель *не умеет* читать PDF и
  фотографии. Описывайте содержимое файла в этих полях, иначе файл невидим.

---

## 2. Что именно векторизуется

Каждая запись перед эмбеддингом собирается в каноническую строку
([services/embeddings.py:16-35](../services/embeddings.py#L16-L35)):

```
Title: <название>. Category: <категория>. Keywords: <кв1, кв2, ...>. Content: <контент>
```

Пустые секции пропускаются. Затем строка получает префикс `passage: ` (для
хранимых записей) или `query: ` (для вопросов пользователя) — это соглашение
модели E5, которое заметно улучшает качество поиска.

**Почему формат важен:** модель видит одно длинное предложение. Заполненные
все четыре поля дают эмбеддингу несколько «зацепок» — один вопрос попадёт
через заголовок, другой через ключевое слово, третий через формулировку в
контенте. Все они дают примерно одну область векторного пространства.

## 3. Записи базы знаний — справочник по полям

### 3.1 `title` (необязательно, но очень желательно)

Короткое отличительное существительное с пояснением. 2–8 слов.

- ✅ `Льготная стипендия для социально уязвимых студентов`
- ✅ `Процедура Add/Drop (замена дисциплин)`
- ✅ `Военная кафедра — условия поступления`
- ❌ `Информация` (ничего не говорит)
- ❌ `Стипендии КБТУ: виды, условия получения, размер выплат и порядок подачи
  заявления через WSP` (слишком длинно — это задача content)

Заголовок — самый сильный одиночный сигнал для эмбеддинга. Сформулируйте его
так, как сформулировал бы запрос сам студент.

### 3.2 `content` (обязательно)

**Это единственный текст, который увидит LLM.** Системный промпт жёсткий:
*отвечай исключительно на основе `<knowledge>`*. Если чего-то нет в контенте,
бот не сможет этого сказать.

**Пишите полный, самодостаточный ответ.** Раскройте применимые из «семи
вопросов»:

| Вопрос | Пример |
|---|---|
| **Что** это | «Add/Drop — это первая неделя семестра, когда можно добавить, удалить или заменить дисциплину». |
| **Кто** имеет право | «Все бакалавры; магистратура по другим правилам». |
| **Где** / через какой портал | «Через WSP → Academic → Add/Drop request». |
| **Когда** — дедлайны, даты | «Заявки принимаются до 13:00 пятницы первой недели». |
| **Как** — пошагово | «1. Зайти в WSP. 2. Открыть Add/Drop. 3. Выбрать курс. ...» |
| **Сколько** — стоимость | «Пересдача одного курса — 35 000 ₸». |
| **Контакты** — телефон/email/кабинет | «Офис регистратора, C-114, registrar@kbtu.kz». |

**Длина:** столько, сколько нужно ответу. Типично 200–800 символов. Не
раздувайте и не сжимайте насильно. Если нужны шаги — используйте
нумерованный список, LLM сохранит структуру.

**Язык:** пишите на языке, на котором задают вопросы. Для КБТУ это обычно
**русский**. Английские термины можно смешивать, если студенты их так и
используют (`add/drop`, `retake`, `GPA`). Модель мультиязычная, качеству
поиска это не вредит.

**Разнообразьте лексику.** Если у темы есть распространённый английский и
русский термин — включите оба (в title, content или keywords). Например:
`retake / ретейк / пересдача`. Это резко повышает recall, когда студенты
формулируют один и тот же вопрос по-разному.

**Не пишите отказы и мета-текст** («если не знаете, обратитесь...»). У LLM
своя фраза отказа. В content — только факты.

### 3.3 `category` (необязательно, но полезно)

Короткий slug в нижнем регистре. По возможности переиспользуйте существующий
— новые slug фрагментируют поиск и засоряют админку.

Существующие категории видны в списке файлов/знаний админки. Перед созданием
новой прокрутите туда и подберите ближайшую.

- ✅ `academic`, `finance`, `dorm`, `schedule`, `documents`, `registrar`
- ❌ `Academic`, `ACADEMIC`, `Академ.`, `академ. вопросы` (разный регистр и
  форматирование — система нормализует в lowercase, но лишние варианты
  запутывают админов)

### 3.4 `keywords` (необязательно, но мощно)

Список из 5–15 коротких токенов через запятую. Цель: покрыть слова, которые
студент *может набрать*, но которых нет дословно в контенте.

- Включайте **сокращения**: `рупы`, `руп`, `RUP`
- Включайте **транслитерацию** в обе стороны: `retake`, `ретейк`, `ретак`
- Включайте **синонимы и сленг**: `общага` вместо «общежитие», `кафедра`
- Включайте **частые опечатки**, если они действительно частые
- НЕ включайте полные предложения — они не помогут ни эмбеддингу, ни
  фильтру ключевых слов для файлов

У поля keywords две функции:

1. Оно добавляется в эмбеддируемую строку и обогащает вектор.
2. Оно используется **fallback-фильтром файлов** как подстрочное совпадение
   без учёта регистра. Если ни одно ключевое слово не встречается в запросе
   пользователя буквально, файл через fallback не прикрепится. (См. 4.4.)

## 4. Записи файлов — справочник по полям

Файлы требовательнее записей базы знаний, потому что **модель не видит их
содержимое**. Фото карты — это просто байты, PDF с учебным планом — тоже
просто байты. Все сигналы о том, *что внутри*, должны быть в полях, которые
вы заполните.

### 4.1 `title` (настоятельно рекомендуется)

Полное человекочитаемое название файла. Не имя файла в файловой системе.

- ✅ `РУП ВТиПО 2024-2025`
- ✅ `Карта корпуса КБТУ`
- ✅ `Инструкция по Add/Drop — для студентов ШИТиИ`
- ❌ `document.pdf`
- ❌ `Screenshot 2024-10-12`
- ❌ `#карта` (это хештег для caption, а не название)

### 4.2 `caption` (обязательно — здесь вы описываете файл)

От одного до трёх предложений о том, что внутри. Представьте, что читатель
не может открыть файл. Упомяните ключевые термины, которые есть в файле —
названия дисциплин, офисов, процедур, потому что *именно с ними* будет
сравнивать эмбеддинг-модель.

Хороший caption для PDF по Add/Drop:

> Техническая инструкция (гайд) по процедуре Add/Drop (адд дроп, регистрация
> на дисциплины) для студентов ШИТиИ (SITE). Руководство по работе с порталом
> WSP (wsp.kbtu.kz). Правила добавления (ADD), удаления (DROP) и замены
> (REPLACE) предметов. Ограничения по времени (дедлайн до 13:00), даты
> регистрации, запрет на замену осенних дисциплин на весенние. Значение
> статусов заявки (Подан/Filed, Одобрено). Контакты деканата и офиса
> регистратора.

Этот caption насыщен искомыми терминами (`Add/Drop`, `адд дроп`, `WSP`,
`ADD`, `DROP`, `REPLACE`, `дедлайн`, `статус`, `деканат`) без воды.

Плохой caption:

> `#карта`  ← один хештег ничего не даёт эмбеддингу

### 4.3 `category`

Те же правила, что и для категорий знаний. Короткий slug в нижнем регистре.
Типичные для файлов: `map`, `rup`, `calendar`, `syllabus`. Категория
автоопределяется по хештегу в Telegram-посте
([bot/handlers/files.py:10-14](../bot/handlers/files.py#L10-L14)), но админ
должен после этого её нормализовать.

### 4.4 `keywords` — **не пропускайте это поле**

Чтобы файл прикрепился через векторный fallback, хотя бы одно ключевое слово
должно встречаться в запросе пользователя как подстрока без учёта регистра.
Это жёсткий фильтр. Файл без keywords может быть прикреплён только через
курированный путь (явная привязка к записи знаний).

Эмпирика:

- Включайте главные существительные по теме файла. Карта: `карта`, `map`,
  `корпус`, `кбту`. РУП: `руп`, `rup`, `учебный план`, `vtipo`, `вт`.
- Включайте код специальности, если применимо (`vtipo`, `ios`, `fce`).
- Короткие токены лучше. Фильтр ищет подстроку: `учебный план` совпадёт с
  запросом `рабочий учебный план`, но `рабочий учебный план на 2024-2025`
  НЕ совпадёт с запросом `учебный план`.
- 5–10 ключевых слов — хорошо. Больше — нормально. Меньше трёх — рискованно.

### 4.5 Курированные связи — основной путь

В форме редактирования знаний есть мультиселект **«Прикреплённые файлы»**.
Пользуйтесь им. Всякий раз, когда у записи знаний есть очевидно связанный
файл, привязывайте их явно. Бот прикрепит этот файл безусловно при
извлечении записи — без порога, без фильтра ключевых слов.

Именно этот путь делает прикрепление файлов надёжным. Keywords + векторный
fallback — страховочная сетка для вопросов, на которые запись знаний не
попадает по совпадению.

## 5. Проверка записи — Лаборатория

После добавления или редактирования откройте **🧠 Лаборатория** в админ-панели
и прогоните несколько реалистичных запросов. Для каждого запроса вы увидите:

- Топ-3 совпадения по знаниям с косинусным расстоянием. Ваша только что
  записанная запись должна оказаться в верхних строках для тех запросов, на
  которые она должна отвечать.
- Топ-5 файлов с расстояниями, попадают ли их keywords в запрос, разрыв до
  следующего кандидата и итоговое решение фильтра (`🎯 Filter selects:` /
  `⛔ Filter rejects all candidates`).

**Делайте это до закрытия формы.** Итерируйтесь: если ожидаемый запрос не
совпадает или стоит низко — добавьте ключевое слово или перефразируйте
предложение в контенте, сохраните, попробуйте снова.

## 6. Анти-паттерны

| Анти-паттерн | Почему плохо | Как исправить |
|---|---|---|
| Caption из одного слова (`#карта`) | Эмбеддингу не с чем сравниваться | Написать полноценный caption |
| Title = имя файла (`document.pdf`) | То же; имя файла обычно бессмысленно | Использовать человеческое название |
| Контент набит ключевыми словами без предложений | E5 ждёт естественный текст; дамп ключей плохо векторизуется | Ключевые слова — в поле `keywords`, в `content` — проза |
| Контент «см. файл» | LLM не умеет открывать файлы, отвечать будет нечем | Вставить ответ прямо в `content` И прикрепить файл |
| Новая категория под каждую запись | Фрагментируется пространство категорий | Переиспользовать существующие slug |
| Только русский для термина, который часто пишут по-английски (`retake`) | Запрос `retake` не найдёт запись | Добавить английский термин в `keywords` или `content` |
| Копия записи с мелкими правками | Два почти одинаковых вектора конкурируют и делят топ-K | Слить в одну полную запись |
| Правка файла мимо админ-формы | Эмбеддинг не пересчитывается, метаданные устаревают | Всегда сохранять через админ-форму — она пересчитает сама |

## 7. Разобранные примеры

### 7.1 Хорошая запись знаний

```
Title:    Процедура Add/Drop (замена дисциплин)
Category: academic
Keywords: add/drop, add drop, адд дроп, замена дисциплин, drop, replace,
          wsp, регистрация на предметы, первая неделя семестра
Content:
Add/Drop — это первая неделя семестра, в течение которой студент может
добавить (ADD), удалить (DROP) или заменить (REPLACE) дисциплину в своём
расписании через портал WSP (wsp.kbtu.kz).

Как подать заявку:
1. Зайдите в WSP → раздел Academic → Add/Drop request.
2. Выберите действие (ADD / DROP / REPLACE) и дисциплину.
3. Подтвердите заявку — статус изменится на "Подан" (Filed).
4. Дождитесь одобрения офиса регистратора — статус станет "Одобрено".

Ограничения:
- Дедлайн: пятница первой недели семестра до 13:00.
- Осенние дисциплины нельзя заменять на весенние.
- После дедлайна изменения возможны только через апелляцию в деканат.

Контакты: офис регистратора, корпус C, каб. 114, registrar@kbtu.kz.
```

Почему работает:
- Title — фраза, которую студент может набрать как запрос.
- Content раскрывает что/как/когда/где/контакты.
- Keywords включают английский, русский, транслит, синонимы.
- Category — переиспользованный slug.

### 7.2 Хорошая запись файла

```
Title:    Инструкция по Add/Drop — для студентов ШИТиИ
Category: academic
Keywords: add/drop, add drop, адд дроп, замена дисциплин, wsp, site, шитии,
          регистрация, дедлайн, drop, replace
Caption:
Техническая инструкция (гайд) по процедуре Add/Drop для студентов ШИТиИ
(SITE). Пошаговое руководство по работе с порталом WSP (wsp.kbtu.kz),
правила добавления (ADD), удаления (DROP) и замены (REPLACE) дисциплин.
Дедлайны, статусы заявки (Подан/Filed, Одобрено), ограничения на замену
осенних дисциплин на весенние, контакты деканата ШИТиИ и офиса регистратора.

Привязан к записи знаний: «Процедура Add/Drop (замена дисциплин)»
```

Почему работает:
- Caption описывает *содержимое*, а не «это гайд».
- Keywords покрывают разные формулировки.
- Привязан к соответствующей записи — прикрепляется всегда при её
  извлечении, не зависит от векторного fallback.

### 7.3 Плохая запись — до и после

**До:**

```
Title:    (пусто)
Category: info
Keywords: (пусто)
Content:  Ретейк 35000.
```

Проблемы: нет title, размытая категория, нет keywords, контент слишком
краткий для полезного ответа LLM.

**После:**

```
Title:    Стоимость и процедура пересдачи (Retake)
Category: finance
Keywords: ретейк, retake, ретак, пересдача, цена, стоимость, оплата
Content:
Пересдача одного курса (retake) стоит 35 000 ₸. Оплата производится через
Kaspi по реквизитам КБТУ до подачи заявки на пересдачу. Подать заявку
можно через офис регистратора (корпус C, каб. 114) в течение первых двух
недель следующего семестра. Необходимые документы: копия квитанции об
оплате, заявление на имя регистратора.
```

## 8. Диагностика проблем

**«Моя запись не ловится запросами, которыми должна».**
Откройте Лабораторию. Если расстояние `> 0.35` на разумном запросе —
эмбеддинг слабый. Частые причины: слишком короткий контент, лексика не
пересекается с типичными запросами, нет keywords. Перепишите контент так,
чтобы в нём были слова, которые реально используют студенты.

**«Файл не прикрепляется, хотя явно подходит».**
Три вещи для проверки в Лаборатории:
1. Расстояние файла ≤ 0.20? Если нет — усиливайте caption/title/keywords.
2. Есть ли хотя бы одно keyword, буквально встречающееся в тестовом запросе?
3. Есть ли «шумный» файл близко сзади (разрыв < 0.05)? Если да — либо
   (а) добавьте более отличительное keyword в файл-лидер, либо (б) добавьте
   keywords к шумному файлу, чтобы сравнение разрыва шло между двумя файлами
   с совпадающими keywords.
Если ничего не помогает — используйте **курированную связь**, привяжите
файл к нужной записи знаний. Это полностью обходит векторный fallback.

**«Бот отвечает, но упускает деталь, которая есть в моём контенте».**
У LLM лимит ответа 1024 токена, инструкция — держаться контекста. Если
контекст очень длинный, модель может сжимать. Разделите одну огромную запись
на 2–3 сфокусированных (например, отдельно «кто имеет право», отдельно
«процедура», отдельно «стоимость»).

**«Бот отказывается отвечать, хотя запись есть».**
Расстояние `> 0.35` — фильтр отсёк запись. Улучшайте title, content и
keywords, чтобы вектор оказался ближе к запросу. Перепроверьте в
Лаборатории.

---

## 9. Чек-лист перед сохранением

Для каждой записи **знаний**:

- [ ] Title 2–8 слов и отличителен
- [ ] Content — полный ответ: кто/что/где/когда/как/сколько/контакты
- [ ] Content написан на языке, которым пользуются студенты (обычно русский)
- [ ] Альтернативные термины (англ + рус + сокращения) встречаются где-то
- [ ] Category — переиспользованный slug в нижнем регистре
- [ ] В keywords 5–15 коротких токенов
- [ ] Все релевантные файлы привязаны через мультиселект
- [ ] Проверено в Лаборатории на 2–3 реалистичных запросах

Для каждой записи **файла**:

- [ ] Title — человекочитаемое название (не имя файла)
- [ ] Caption описывает *что внутри* в 1–3 предложениях с конкретными
      терминами
- [ ] Category — переиспользованный slug в нижнем регистре
- [ ] В keywords ≥ 5 токенов, включая короткие существительные, которые
      наберёт пользователь
- [ ] Привязан хотя бы к одной записи знаний (если возможно) — это
      надёжный путь
- [ ] Проверено в Лаборатории на ожидаемом запросе; решение фильтра —
      `🎯 Filter selects`
